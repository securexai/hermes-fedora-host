Hermes Agent on Fedora Server 44

Current disposable DeepSeek lab: use the lab procedure. This page retains the dedicated physical-host and encrypted production-candidate path; its older certification steps do not describe the unencrypted lab.

This guide is the operator reference for the dedicated Hermes appliance at 10.0.30.10. The active implementation targets Fedora Server 44 x86_64, rootless Podman, LUKS-backed storage, UEFI Secure Boot, enforcing SELinux, firewalld, and an SSH-only host boundary.

Promotion is mandatory

A disposable Fedora Server VM must pass the complete controller, provider, authenticated inference, credential cleanup, purge, and destruction flow before production can be changed. The certifier verifies local installation media and does not download it. It prints a promotion record only after the VM is gone.

Operator inputs (export these first). HERMES_REPO defaults to the current checkout location; set it if your checkout is elsewhere. HERMES_SSH_IDENTITY must be the SSH private key you have independently verified for the target.

HERMES_REPO=${HERMES_REPO:-$HOME/code/repos/hermes-fedora-host}
HERMES_MEDIA_DIR=${HERMES_MEDIA_DIR:-$HOME/Downloads/fedora-server-44-1.7}
HERMES_SSH_IDENTITY=${HERMES_SSH_IDENTITY:?export the verified SSH private key path}
cd "$HERMES_REPO"

Certification runs from the repository root with the locally downloaded, signature-verified Server media:

./hermes-certify-vm.sh \
  --iso "$HERMES_MEDIA_DIR/Fedora-Server-dvd-x86_64-44-1.7.iso" \
  --checksum "$HERMES_MEDIA_DIR/Fedora-Server-44-1.7-x86_64-CHECKSUM" \
  --fedora-keyring "$HERMES_MEDIA_DIR/fedora.gpg" \
  --identity-file "$HERMES_SSH_IDENTITY" \
  --provider openai-codex \
  --model gpt-5.6-luna

Fedora publishes the Server DVD and its signed-checksum workflow at the official Server download page. The expected x86_64 Server 44 1.7 DVD SHA-256 is 85837793bfa36db6bc709b4cecd2ec116951b87d9c53c3d95eb2fac8dcf7cf1f.

After the automated reboot and credential-free acceptance gates, the certifier requires ENCRYPTED_REBOOT_EVIDENCE_OK watched_boots=3, then prints AUTHENTICATION_READY provider=<id> and waits. The persistent watcher re-arms only after Fedora emits an explicit reboot marker, starts the encrypted-root systemd-cryptsetup@luks... unit, and then displays the exact prompt. In-place terminal repaint bytes may precede that exact start marker. If systemd middle-ellipsizes the escaped unit as luks\x…<UUID-tail>, the retained tail must begin with hexadecimal data. Generic path-units progress is ignored because Fedora emits it both before and after unlock. A same-boot cryptsetup redraw without a fresh reboot marker cannot arm the watcher. Missing, duplicate, cross-boot, or out-of-order prompt evidence fails closed before OAuth and is checked again before promotion. START-AUTH is a readiness response consumed by that running certifier, not a shell command. Enter it in the same certification terminal. Provider authentication—and the 15-minute openai-codex device-login window—starts only after this confirmation.

Reinstalled production host

At the physical console, verify the new SSH ED25519 host fingerprint before updating the workstation's known-hosts entry. Then archive the previous local state and bind the new installation to its SSH fingerprint and machine-id:

cd "$HERMES_REPO"

./hermes-deploy.sh adopt-host \
  --target aicowork@10.0.30.10 \
  --identity-file "$HERMES_SSH_IDENTITY" \
  --management-cidr 192.168.99.0/24 \
  --interface eno1

Type ADOPT-HERMES-HOST when prompted. The command moves legacy $HOME/hermes-deploy state to a timestamped archive; it does not delete it.

Read-only production preflight

cd "$HERMES_REPO"

./hermes-deploy.sh check \
  --target aicowork@10.0.30.10 \
  --identity-file "$HERMES_SSH_IDENTITY" \
  --management-cidr 192.168.99.0/24 \
  --interface eno1

check verifies the Server platform, SSH/sudo inspection, Podman, storage, Secure Boot, SELinux, firewalld, networking, listeners, and host state. It does not create deployment state or mutate the host.

Production deployment

Use the exact provider and model that the promotion record names. The controller asks for one typed production confirmation before package mutation and planned reboots. It uses DNF5 offline update preparation, then configures download-only automatic updates (apply_updates=False, reboot=never).

cd "$HERMES_REPO"

./hermes-deploy.sh deploy \
  --target aicowork@10.0.30.10 \
  --identity-file "$HERMES_SSH_IDENTITY" \
  --management-cidr 192.168.99.0/24 \
  --interface eno1 \
  --provider openai-codex \
  --model gpt-5.6-luna \
  --promotion-record /absolute/path/to/promotion-*.record

Provider choices and billing

All credential prompts run in the terminal. No API-key option is accepted by the shell command, and credentials are not written to controller state, logs, process arguments, or the promotion record.

  • openai-codex: ChatGPT/Codex subscription device-code OAuth. Subscription access and API usage billing are separate products.
  • openai-api: OpenAI API-key prompt with usage-based API billing.
  • nous: Nous Portal OAuth and Portal billing.

Each provider/model combination needs a new VM certification record.

./hermes-deploy.sh configure-provider \
  --target aicowork@10.0.30.10 \
  --identity-file "$HERMES_SSH_IDENTITY" \
  --management-cidr 192.168.99.0/24 \
  --interface eno1 \
  --provider openai-codex --model gpt-5.6-luna \
  --promotion-record /absolute/path/to/promotion-*.record

./hermes-deploy.sh configure-provider \
  --target aicowork@10.0.30.10 \
  --identity-file "$HERMES_SSH_IDENTITY" \
  --management-cidr 192.168.99.0/24 \
  --interface eno1 \
  --provider openai-api --model gpt-5.6-luna \

Acceptance and maintenance

Provider authentication and the exact authenticated response HERMES_OK remain manual account gates. The controller verifies the configured provider/model after restart and revokes credentials for the other supported providers after a successful switch.

./hermes-deploy.sh status --target aicowork@10.0.30.10 \
  --identity-file "$HERMES_SSH_IDENTITY" \
  --management-cidr 192.168.99.0/24 --interface eno1

./hermes-deploy.sh revoke-auth --provider openai-api \
  --target aicowork@10.0.30.10 \
  --identity-file "$HERMES_SSH_IDENTITY" \
  --management-cidr 192.168.99.0/24 --interface eno1

./hermes-deploy.sh rollback --target aicowork@10.0.30.10 \
  --identity-file "$HERMES_SSH_IDENTITY" \
  --management-cidr 192.168.99.0/24 --interface eno1

Rollback restores Hermes and manifest-tracked host configuration. It never claims to reverse Fedora RPM or kernel updates. Keep SSH console recovery available for boot and storage recovery.
